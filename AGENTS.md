# AGENTS.md

This file is the working contract for coding agents in CopyWeave.

## Mission

Let a human edit website copy in the real composition without changing the normal design or handing content to a hosted CMS.

## Non-negotiable invariants

1. Normal viewing must not show editor chrome, outlines, layout boxes, or intercepted links.
2. User copy is plain text. Never send it through `innerHTML`.
3. `data-copy-id` is the durable identity. Automatic IDs must stay visibly diagnostic.
4. “Saved to project” is only valid after the loopback endpoint confirms disk write.
5. The CLI binds to loopback by default and keeps runtime dependencies at zero.
6. Invalid imports and save conflicts must preserve the previous valid content.
7. Editor copy, API names, schema, CLI output, and Skill instructions change together.

## Repository map

In a source checkout or extracted release tarball, the paths below are present. When CopyWeave is installed only as another project's dependency, do not run this repository's development scripts from inside `node_modules`; use the shipped `dist`, `bin`, `schema`, `docs`, and `skill` surfaces instead.

- `src/`: browser runtime. `editor.ts` orchestrates; keep discovery, schema, storage, panel, and styles isolated.
- `bin/copyweave.mjs`: dependency-free Node CLI and loopback server.
- `schema/`: public content contract.
- `demo/`: dogfood site with semantic leaf fields.
- `tests/`: browser-model and real-HTTP CLI tests.
- `skill/copyweave-integrator/`: independently publishable Agent Skill.
- `docs/`: architecture, security, integration, release, and review evidence.
- `dist/` and `demo/assets/copyweave.iife.js`: generated by `npm run build`; do not hand-edit.

## One verification command

```bash
npm run check
```

It must pass before delivery. For a UI change, also run the demo, inspect desktop and mobile, test keyboard/IME, save to disk, reload, and close the editor to compare normal mode.

## Change workflow

1. Read the nearest source and its tests.
2. State which invariant the change touches.
3. Add or update a failing test.
4. Make the smallest implementation change.
5. Run focused tests, then `npm run check`.
6. Update README, schema, Skill, or changelog if the public contract changed.
7. Record visual proof for UI changes.

## Security boundaries

- Treat HTML, imported JSON, headers, URL paths, config messages, and field IDs as untrusted.
- Keep session tokens in memory and same-origin requests only.
- Require ETag preconditions for writes.
- Resolve real paths before serving files; never widen the static root from request input.
- Bound body, page, field, key, and copy sizes.
- Use unique same-directory temporary files and atomic rename.
- Do not add network calls, analytics, secrets, or remote fonts to core or demo.

## AI-friendly output

CLI automation must support stable exit codes and `--json`. Diagnostics need a durable `code`, human `message`, and file/field when known. Do not make agents scrape color or prose to detect failure.
